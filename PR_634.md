Closes #634

## Summary

Checkout sessions can now collect a shipping address from the payer, offer fixed shipping rates and copy the collected address to the customer record.

### Changes

- `CreateCheckoutSessionDto`:
  - `shippingAddressCollection: { allowedCountries: string[] }` (ISO 3166-1 alpha-2; empty list = unrestricted)
  - `shippingOptions: [{ id, label, amount }]` (up to 20 fixed rates in minor units)
  - `shippingOptionId` to preselect a rate at creation
  - Swagger decorators for all new fields and responses
- New public endpoint `POST /v1/checkout/sessions/:publicId/shipping-address`:
  - validates required address fields and the ISO country code
  - rejects countries outside the merchant allowlist and unknown shipping options
  - stores the address on the session and adds the selected rate to the total
  - returns `shippingFormatted` separately from the subtotal and total
- `CheckoutSession` entity and reversible TypeORM migration `1792800000000-AddCheckoutSessionShipping`
  (`shippingAddressCollection`, `shippingOptions`, `shippingAddress`, `shippingOptionId`,
  `shippingAmount` on `checkout_sessions`; `shippingAddress` on `customers`).
- On `checkout.session.completed` the address is copied to an existing customer (or a new one is created for the payer email). Shipping data is included in the completion webhook payload and payment metadata so it can be shown on receipts.
- Coupon apply/remove now preserves the shipping amount (`total = subtotal - discount + shipping`).
- Docs updated: `docs/CHECKOUT_SESSIONS.md`, `docs/CUSTOMERS.md`.
- Tests: 15 new unit tests (service logic), 4 new e2e tests (main endpoints), 1 migration reversibility test. Two broken fixtures in the existing `checkout-sessions.service.spec.ts` were corrected (expired-substitution case and stale-session cron fixtures).
